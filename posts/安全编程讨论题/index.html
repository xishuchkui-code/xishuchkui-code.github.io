安全编程

2026-06-15

某媒体解析库处理文件索引表时遇到了恶意攻击。已知文件格式如图所示：

/*
 * read_uint32_from_file(file)：
 * 从当前文件位置读取4字节并解释为 uint32_t，
 * 同时文件读指针自动向后移动4字节。
 * 每次调用读取的是不同位置的数据。
 */

typedef struct {
    uint32_t offset;
    uint32_t length;
    uint32_t type;
} ChunkEntry;

/* 文件头中的Chunk数量（攻击者可控） */
uint32_t chunk_count = read_uint32_from_file(file);
uint32_t alloc_size  = chunk_count * sizeof(ChunkEntry);

ChunkEntry *table = malloc(alloc_size);
if (table == NULL)
    return ERROR;

/* 读取Chunk索引表，每个Chunk包含3个字段 */
for (uint32_t i = 0; i < chunk_count; i++) {
    table[i].offset = read_uint32_from_file(file); /* 偏移量 */
    table[i].length = read_uint32_from_file(file); /* 长度   */
    table[i].type   = read_uint32_from_file(file); /* 类型   */
}

请回答：

  1. 缺陷在哪里？ 指出存在安全隐患的具体代码行，说明原因。
  2. 攻击链怎么构成？ 攻击者需要控制什么？什么时候触发堆溢出？堆上会发生什么？
  3. 你认为如何用一行代码修复这个问题？（选做，有想法就写）

4. 缺陷在哪里？

  • 缺陷行：uint32_t alloc_size = chunk_count * sizeof(ChunkEntry);
  • 原因：整数溢出（Integer Overflow）
  • chunk_count 是 uint32_t，攻击者可控
  • sizeof(ChunkEntry) = 12（3 × 4 字节）
  • 两者相乘的结果仍被存入 uint32_t（最大值 ~4.29 × 10⁹）
  • 当 chunk_count 足够大时，乘积超出 uint32_t 范围发生回绕，例如：
    • chunk_count = 0x15555556 (357,913,942)
    • × 12 = 0x100000008
    • uint32_t 截断 = 0x00000008 ← 只有 8 字节！
  • malloc(8) 成功返回，但 table 实际只有 8 字节。

1. 攻击链怎么构成？

  • 攻击者控制文件头的 chunk_count 字段

    • │
    • ▼

  • 选取特殊值使乘法溢出

    • 例如 chunk_count = 0x15555556
    • │
    • ▼

  • alloc_size = 0x00000008（仅 8 字节）

  • malloc(8) 成功返回，table 不为 NULL

    • │
    • ▼ ← 触发点：进入 for 循环

  • 循环执行 357,913,942 次

  • 每次写入 12 字节到 table[i]

  • 但堆上只有 8 字节合法空间

    • │
    • ▼

  • 堆溢出（Heap Overflow）

    覆盖相邻堆块的 header/metadata 覆盖其他对象（函数指针、vtable、fd/bk 指针） → 最终可能实现任意地址写，进而 RCE

2. 一行修复

if (chunk_count == 0 || chunk_count > SIZE_MAX / sizeof(ChunkEntry)) return ERROR;

原理：用除法反推来检查，完全避免溢出本身的发生。若 chunk_count > SIZE_MAX / 12，说明乘法必然溢出，直接拒绝。
